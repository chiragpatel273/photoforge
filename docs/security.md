# Security and data ownership

Sessions are signed JWTs in HTTP-only, SameSite=Lax cookies, Secure in production. Normal sessions expire after seven days; guests after 24 hours. An authenticated request reloads the user and checks a session-version counter and guest expiry. Logout increments the counter, revoking all previous tokens for that user. Secrets must be random and supplied through the environment/Secrets Manager; do not enable debug request-header logging.

Passwords use Node scrypt with independent 128-bit random salts, 64-byte derived keys and constant-time comparisons. Login performs a dummy verification for unknown users and returns one generic credential error. Email normalization is applied before database uniqueness. There is no password recovery, verification email or MFA in this MVP.

All mutations reject mismatched Origin headers and cross-site Fetch Metadata. Browser requests use same-origin Next rewrites. Authorization accepts cookies only; no tokens are stored in localStorage. The API is not publicly exposed in Compose/EC2. SameSite cookies and exact-origin checks protect ordinary browser mutation requests; an additional synchronizer CSRF token is a future hardening option for deployments with different origin policies. Do not weaken CORS/Origin settings to make cross-origin deployment work without reviewing that design.

Every book operation filters by authenticated user. Assets must match both user and book, including saved-document references and PDF loading. Export queries authorize through their book relation. Order queries filter by user; an order item snapshots its title and document so deleting a book cannot erase order history. Unowned IDs return 404. The client never supplies an authoritative user ID or total price.

S3 is private with public access blocked. Signatures grant a narrow key/type/length and short expiry; keys are generated by the server rather than interpolating filenames. Upload completion verifies stored metadata. Workers validate actual image decoding, file signature/format, animation, pixel count and decoded dimensions. Original browser-upload keys are never the canonical export source after processing. Metadata is stripped; this does not constitute a comprehensive malware scanner.

The guest workspace is isolated and quotas limit individual account storage/work. Global IP rate limits use Redis; a large public demo still requires WAF/abuse monitoring, costs/budget alarms and appropriate retention. `pnpm cleanup:guests` removes expired guest prefixes and records in batches of 100. Run with a separate cleanup role granting delete access only to `users/*`; this permission is intentionally absent from the default API/worker instance role. Run cleanup during a maintenance window after in-flight jobs have finished. Re-run batches until empty. Member-book deletion does not currently garbage-collect orphan storage; never delete source objects based only on book-prefix ownership because duplicated books share immutable object keys.

Infrastructure exposes only HTTPS/HTTP redirect. RDS is private, encrypted and protected from deletion; Redis is private and uses a persistent volume. EC2 requires IMDSv2 and uses an instance role for AWS credentials. The default role lacks bucket deletion/listing administration or broad Secrets Manager access. The SSM deployment role is powerful; restrict its OIDC trust to this repository's protected `production` environment, protect workflow changes, and scope SendCommand to the application instance.

Guest uploads, generated PDFs, DB records, order snapshots, CloudWatch logs, Terraform state and backups are sensitive data. Define retention and deletion policies before public operation. Do not store actual customer data until backup restore, access logging, runtime dependency scanning and incident procedures have been exercised.
